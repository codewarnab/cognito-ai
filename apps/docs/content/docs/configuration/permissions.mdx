Cognito AI requires specific Chrome permissions to function properly. This page explains what each permission does and why it's needed, helping you understand exactly what access you're granting.

## Permission Categories

Cognito's permissions fall into five main categories:

| Category | Examples | Purpose |
|----------|----------|---------|
| **Core** | sidePanel, storage | Basic functionality |
| **Tab Access** | tabs, activeTab | Read page content |
| **Scripting** | scripting | Inject content scripts |
| **Host** | `<all_urls>` | Access web pages |
| **Auth** | identity | OAuth for MCP |

---

## Core Permissions

These permissions enable Cognito's fundamental features.

### sidePanel

The `sidePanel` permission allows Cognito to display its AI chat interface as a side panel in your browser. This is Cognito's primary UI — it appears alongside web pages so you can interact with the AI while browsing.

### storage

The `storage` permission lets Cognito persist your settings and data between sessions. This includes user preferences, API keys, MCP tokens, and message history. Without this permission, you'd lose all your data every time you closed the browser.

### unlimitedStorage

Over time, your message history and memory data can grow substantially. The `unlimitedStorage` permission ensures Cognito can store as much data as needed without hitting Chrome's default storage limits.

### alarms

The `alarms` permission enables Cognito to schedule background tasks like token refresh, background content extraction, and other periodic operations that keep the extension running smoothly.

### offscreen

Voice mode requires audio processing that happens behind the scenes. The `offscreen` permission allows Cognito to create invisible documents for processing audio without cluttering your visible UI.

---

## Tab Access Permissions

These permissions let Cognito understand and interact with your browser tabs.

### tabs

The `tabs` permission provides access to tab information. Cognito uses this to read the current page URL, detect when you switch tabs, and send messages between different parts of the extension.

### activeTab

When you're actively working with Cognito, it needs to access the current tab to read page content for AI context and execute browser automation tasks you request.

### Screenshots

Cognito captures screenshots using Chrome’s tab APIs (e.g. `chrome.tabs.captureVisibleTab`). This does **not** require the `tabCapture` permission (which is for audio/video stream capture).

---

## Scripting Permissions

### scripting

The `scripting` permission is essential for Cognito to inject content scripts into web pages, read the page DOM structure, and execute browser actions you request.

---

## Host Permissions

### `<all_urls>`

This permission allows Cognito to access any website you visit. It's needed to read page content on any site, execute browser automation anywhere, and inject the WebMCP proxy to discover available tools.

<Callout title="Privacy Note">
  While Cognito has the technical ability to access any page, it only reads content when you explicitly interact with it — for example, when you ask a question about the current page. Cognito never scans or collects data in the background.
</Callout>

---

## Auth Permissions

### identity

The `identity` permission enables OAuth authentication, which is required for connecting to MCP servers that need OAuth (like Notion or Linear). In the current manifest, this permission is granted at install time and only used when you connect an OAuth-backed MCP server.

## Commands & Shortcuts

Cognito registers keyboard shortcuts to help you work faster:

| Command | Default | Description |
|---------|---------|-------------|
| `_execute_side_panel` | `Ctrl+Shift+H` | Open the side panel |

### Omnibox

You can also interact with Cognito directly from Chrome's address bar using the `ai` keyword. Simply type `ai` in the address bar, press Tab, and enter your command or question.

---

## Content Security Policy

Cognito uses a strict Content Security Policy for enhanced security:

```json
{
  "extension_pages": "script-src 'self' 'wasm-unsafe-eval'; object-src 'self'"
}
```

This policy prevents inline script execution, blocks external script loading, and protects against XSS attacks.

## Web Accessible Resources

The extension exposes certain resources to web pages to enable WebMCP integration. This allows websites that support WebMCP to communicate with Cognito.

## Permission Requests

### Required at Install

When you install Cognito, these permissions are granted automatically:

- `sidePanel` — Display the chat interface
- `storage` — Save your settings and data
- `unlimitedStorage` — Store large local data (chat history, artifacts)
- `tabs` — Access tab information
- `tabGroups` — Organize and manage tab groups
- `activeTab` — Interact with the current page
- `scripting` — Inject content scripts
- `offscreen` — Offscreen documents for background tasks (e.g. audio/voice flows)
- `identity` — OAuth flows for authenticated MCP servers
- `omnibox` — Address-bar keyword integration (`ai`)

### Used Conditionally

Some permissions are powerful but only used when the related feature is enabled or invoked (for example: `identity` only when you connect an OAuth MCP server, or `history` only for features that need it).

<Callout type="info" title="Permission Prompts">
  Chrome may show prompts like "Read and change your data on all websites" or "Sign you in with your Google account." These are standard Chrome permission dialogs — approve them to enable the corresponding features.
</Callout>

## Privacy Implications

Understanding what data each permission exposes is important:

| Permission | Data Access | Privacy Impact |
|------------|-------------|----------------|
| `tabs` | URLs, titles | Can see your browsing history |
| `<all_urls>` | Page content | Can read any page content |
| `storage` | Local data | Stores your data locally |

### How Cognito Protects Your Privacy

Cognito is designed with privacy as a core principle:

1. **Local-first architecture** — All your data stays on your device by default
2. **No tracking** — Cognito includes no analytics, telemetry, or tracking code
3. **Selective access** — Page content is only read when you explicitly interact with it
4. **Secure storage** — All data is stored using Chrome's encrypted storage APIs

For a deeper dive into privacy protections, see the [Privacy Model](/docs/security/privacy-model) documentation.

---

## Minimizing Permissions

If you're concerned about permissions, there are ways to minimize what Cognito can access:

1. **Use Local Mode** — Chrome's built-in AI makes no remote API calls
2. **Disable unused MCP servers** — Only enable integrations you actively use
3. **Use BYOK mode** — Your own API key means no data goes through our backend
