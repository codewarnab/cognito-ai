The **CLI Bridge** is a local server that enables **Code Mode** in Cognito. It connects CLI-based AI coding agents (Gemini CLI, Claude Code, Codex CLI) to your browser, allowing them to use Cognito's browser automation tools.

## Getting Started

```bash title="Terminal"
npx @cognito/cli-bridge
```

That's it! The bridge starts on `localhost:8787` and the extension auto-connects when you enable Code Mode.

<Callout type="info">
  **Sandbox Mode**: By default, agents run in an isolated sandbox with **no access to your local file system**. This prevents agents from reading your project files or executing dangerous commands.
</Callout>

## Why MCP Server?

<Callout>
  **Claude Code uses MCP for tools.** The Model Context Protocol (MCP) is how Claude Code discovers and executes custom tools. The CLI Bridge exposes Cognito's browser tools as an MCP server, allowing Claude Code to seamlessly use them alongside its built-in capabilities.
</Callout>

All three supported agents (Gemini CLI, Claude Code, Codex CLI) use the Vercel AI SDK, but Claude Code specifically requires tools to be exposed via MCP - it cannot use arbitrary function definitions like other providers.

## Architecture Overview

<CliBridgeArchitectureDiagram />

The bridge handles:

- **Secure pairing** with the extension via token-based authentication
- **Streaming responses** back to the extension via Server-Sent Events (SSE)
- **Tool execution** — browser tools are exposed to CLI agents
- **MCP server** — required for Claude Code tool integration

## How It Works

### Connection Flow

<CliBridgeConnectionSequence />

1. Extension calls `/health` to check if bridge is running
2. Extension authenticates via `/connect` with origin validation
3. Token stored for future sessions
4. Extension registers its browser tools

### Chat Flow

<CliBridgeChatSequence />

When you send a message in Code Mode:

1. **Extension → Bridge**: POST `/cli/chat` with messages and agent selection
2. **Bridge routes to handler**: Based on agent type (Gemini, Claude Code, or Codex)
3. **Agent processes request**: Uses Vercel AI SDK to stream completion
4. **Tool execution loop**: 
   - Agent requests tool (e.g., `clickByText`)
   - Bridge sends request to extension via SSE
   - Extension executes tool in browser
   - Result sent back to bridge
5. **Response streams back**: Text and tool results flow to extension UI

### Agent Handlers

Each agent has a dedicated handler that processes requests:

| Agent | Handler | How Tools Work |
|-------|---------|----------------|
| **Gemini CLI** | `handleGeminiAgent()` | AI SDK tools via function definitions |
| **Claude Code** | `handleClaudeCodeAgent()` | AI SDK tools via MCP server |
| **Codex CLI** | `handleCodexAgent()` | AI SDK tools via function definitions |

### Tool Approval Flow

<CliBridgeToolApprovalSequence />

Sensitive browser actions require user approval before execution, implementing a human-in-the-loop pattern.

## Security

<Callout type="warn">
  **Localhost Only**: The bridge binds exclusively to `127.0.0.1` - it cannot be accessed from other machines.
</Callout>

<Callout type="warn">
  **Origin Validation**: In **production** (`NODE_ENV=production`), only requests from the specific Cognito extension ID (set via `EXTENSION_ID` env var) are accepted. In **development**, any Chrome extension origin is allowed for easier testing.
</Callout>

<Callout type="warn">
  **Token Authentication**: All sensitive endpoints require a token that is SHA-256 hashed before storage in `~/.cognito/bridge/tokens.json`.
</Callout>

<Callout type="warn">
  **Sandbox Isolation**: Agents run in a temporary directory with no access to your local files. To disable (not recommended): set `COGNITO_BRIDGE_ALLOW_LOCAL_ACCESS=true`.
</Callout>

## CLI Options

```bash title="Terminal"
npx @cognito/cli-bridge --help
```

| Option | Default | Description |
|--------|---------|-------------|
| `--port` | `8787` | Port to listen on |
| `--host` | `127.0.0.1` | Host to bind to |
| `--gemini-model` | `gemini-2.5-flash` | Model ID for Gemini |
| `--no-auto-setup` | - | Skip CLI tool auto-configuration |

## Authentication

<Callout type="info">
  **OAuth Support**: All three CLI agents (Gemini CLI, Claude Code, Codex CLI) support **OAuth authentication**. If you've already logged in via the CLI tools, the bridge will use your existing session and subscription plan automatically.
</Callout>

API keys are **optional** and only needed if you want to use your own key (BYOK) instead of OAuth:

| Variable | Agent | Description |
|----------|-------|-------------|
| `GEMINI_API_KEY` | Gemini CLI | Optional - uses OAuth if not set |
| `ANTHROPIC_API_KEY` | Claude Code | Optional - uses OAuth if not set |
| `OPENAI_API_KEY` | Codex CLI | Optional - uses OAuth if not set |

### Model Configuration

You can customize which model each agent uses via environment variables:

| Variable | Default | Description |
|----------|---------|-------------|
| `COGNITO_GEMINI_MODEL` | `gemini-2.5-flash` | Model for Gemini CLI |
| `CLAUDE_CODE_MODEL` | `sonnet` | Model for Claude Code |
| `CODEX_MODEL` | `gpt-5.1-codex` | Model for Codex CLI |

<Callout type="tip">
  **Model Selection**: You can also select any available model directly from the model picker dropdown in the extension interface, overriding these defaults without restarting the bridge.
</Callout>
