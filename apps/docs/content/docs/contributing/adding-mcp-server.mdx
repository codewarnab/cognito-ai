This guide walks you through adding support for a new MCP server to Cognito AI.

## What You'll Learn

- MCP server types and when to use each
- Adding remote (SSE/HTTP) servers
- Configuring authentication (OAuth, PAT, hybrid)
- Testing your integration

<Callout type="warn">
The backend is not open source. StdIO servers that require backend proxying are configured by maintainers only. This guide focuses on remote MCP servers that connect directly from the extension.
</Callout>

## Server Types

| Type | Transport | Who Can Add |
|------|-----------|-------------|
| **Remote (SSE/HTTP)** | Direct browser connection | Contributors ✅ |
| **Pre-configured Remote** | Bundled in extension | Contributors ✅ |
| **StdIO (Backend-only)** | Requires backend proxy | Maintainers only |

## Adding a Remote MCP Server

### Add Server Configuration

Edit `apps/extension/src/constants/mcpServers.tsx`:

```tsx title="apps/extension/src/constants/mcpServers.tsx"
import { MyServiceIcon } from '@assets/brands/integrations/MyService';
// Or use an image:
import myServiceImage from '@assets/brands/integrations/myservice.png';

export const MCP_SERVERS: ServerConfig[] = [
  // ... existing servers
  
  {
    id: 'my-service',
    name: 'My Service',
    icon: <MyServiceIcon className="w-6 h-6" />,
    // Or for images:
    // icon: <img src={myServiceImage} alt="My Service" style={{ width: 24, height: 24 }} />,
    initialEnabled: false,
    initialAuthenticated: false,
    url: 'https://mcp.myservice.com/mcp',
    description: 'Brief description of what this integration provides.',
    requiresAuthentication: true,  // or false if no auth needed
  },
];
```

### Configuration Schema

```typescript
interface ServerConfig {
  // Required
  id: string;                      // Unique identifier (kebab-case)
  name: string;                    // Display name
  url: string;                     // MCP endpoint URL
  description: string;             // User-facing description
  requiresAuthentication: boolean; // Whether auth is needed
  
  // Required defaults
  initialEnabled: false;           // Always start disabled
  initialAuthenticated: false;     // Always start unauthenticated
  
  // Visual
  icon: React.ReactNode;           // Icon component or image
  
  // Optional
  paid?: boolean;                  // Show "paid" badge
  authConfig?: AuthConfig;         // PAT/OAuth configuration
  oauth?: OAuthConfig;             // OAuth-specific settings
}
```

## Authentication Types

### No Authentication

For public MCP servers:

```tsx
{
  id: 'public-docs',
  name: 'Public Docs',
  url: 'https://mcp.docs.example.com/mcp',
  description: 'Public documentation server.',
  requiresAuthentication: false,
  // ... other required fields
}
```

### OAuth Authentication

For servers supporting OAuth with Dynamic Client Registration (DCR):

```tsx
{
  id: 'oauth-service',
  name: 'OAuth Service',
  url: 'https://mcp.service.com/sse',
  description: 'Service with OAuth authentication.',
  requiresAuthentication: true,
  // OAuth discovery happens automatically via:
  // - RFC 9728: Protected Resource Metadata
  // - RFC 8414: Authorization Server Metadata
}
```

<Callout>
Cognito uses RFC 7591 for Dynamic Client Registration. The server must support a `POST /register` endpoint that returns `client_id`.
</Callout>

### Personal Access Token (PAT)

For servers using API keys or tokens:

```tsx
{
  id: 'token-service',
  name: 'Token Service',
  url: 'https://mcp.service.com/mcp',
  description: 'Service requiring API token.',
  requiresAuthentication: true,
  authConfig: {
    type: 'pat',
    patConfig: {
      label: 'API Key',
      placeholder: 'sk-...',
      helpUrl: 'https://service.com/api-keys',
    },
  },
}
```

### PAT Configuration Options

```typescript
interface PatConfig {
  label: string;              // Input label ("API Key", "Access Token")
  placeholder: string;        // Input placeholder ("sk-...", "ghp_...")
  helpUrl?: string;           // Link to token creation docs
  
  // Token delivery method (pick one):
  // Default: Authorization: Bearer <token>
  authHeaderName?: string;    // Custom header ("X-API-Key")
  urlTokenParam?: string;     // Query param ("?token=xxx")
  urlPathTemplate?: string;   // Path template ("https://api.com/{API_KEY}/mcp")
}
```

### Examples by Token Type

**Custom Header:**

```tsx
authConfig: {
  type: 'pat',
  patConfig: {
    label: 'API Key',
    placeholder: 'Enter your API key',
    authHeaderName: 'X-API-Key',  // Sends: X-API-Key: <token>
  },
}
```

**URL Query Parameter:**

```tsx
authConfig: {
  type: 'pat',
  patConfig: {
    label: 'API Token',
    placeholder: 'Enter your token',
    urlTokenParam: 'token',  // Appends: ?token=<token>
  },
}
```

**URL Path Template:**

```tsx
authConfig: {
  type: 'pat',
  patConfig: {
    label: 'API Key',
    placeholder: 'Enter your API key',
    urlPathTemplate: 'https://mcp.service.com/{API_KEY}/mcp',
  },
}
```

### Multi-Field Authentication

For servers requiring multiple credentials:

```tsx
{
  id: 'multi-field-service',
  name: 'Multi-Field Service',
  url: 'https://mcp.service.com/mcp',
  requiresAuthentication: true,
  authConfig: {
    type: 'pat',
    patConfig: {
      label: 'Credentials',
      placeholder: '',
      fields: [
        { id: 'apiKey', label: 'API Key', placeholder: 'key_...', required: true, secret: true },
        { id: 'workspace', label: 'Workspace ID', placeholder: 'ws-123', required: true },
      ],
    },
  },
}
```

## Adding an Icon

### Option 1: SVG Component

Create a component in `apps/extension/assets/brands/integrations/`:

```tsx title="apps/extension/assets/brands/integrations/MyService.tsx"
export function MyService({ className }: { className?: string }) {
  return (
    <svg className={className} viewBox="0 0 24 24" fill="currentColor">
      {/* SVG paths */}
    </svg>
  );
}
```

### Option 2: Image File

Add an image to `apps/extension/assets/brands/integrations/` and import it:

```tsx
import myServiceImage from '@assets/brands/integrations/myservice.png';

// In config:
icon: <img src={myServiceImage} alt="My Service" style={{ width: 24, height: 24 }} />
```

### Update Icon Mappers

After adding a new server, update the icon mappers:

1. `src/components/ui/tools/icons/McpIconMapper.tsx` — Add import and mapping
2. `src/components/ui/tools/icons/ToolIconMapper.tsx` — Add server name to hints array

## Testing Your Server

### Prerequisites

1. Run `pnpm dev` in the extension directory
2. Load the extension in Chrome

### Test Connection

1. Open extension **Settings** → **MCP Servers**
2. Find your server in the list
3. Enable it
4. Complete authentication if required
5. Verify status shows "Connected"

### Test Tools

1. Open the side panel
2. Ask the AI to use a tool from your server
3. Verify the tool executes correctly

### Debugging

Check the browser console for MCP-related logs:

```
[MCP_CLIENT]
[MCP_AUTH]
[MCP_TOOLS]
```

## Server Requirements

### Required MCP Methods

| Method | Purpose |
|--------|---------|
| `initialize` | Handshake, protocol version |
| `tools/list` | Return available tools |
| `tools/call` | Execute a tool |

### Protocol Versions

Cognito supports:
- `2025-06-18` — Streamable HTTP (preferred)
- `2024-11-05` — HTTP+SSE (fallback)

## Common Issues

### OAuth Discovery Fails

The server may not support Dynamic Client Registration. Check if:
- `/.well-known/oauth-authorization-server` is accessible
- Registration endpoint accepts POST requests
- Server returns valid `client_id`

### Connection Timeout

- Verify the URL is correct and accessible
- Check if the server requires specific headers
- Ensure CORS is configured on the server

### Tools Not Appearing

- Verify `tools/list` returns valid tool definitions
- Check console for parsing errors
- Ensure tool schemas are valid JSON Schema
