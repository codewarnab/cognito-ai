This guide covers coding standards for contributing to Cognito AI.

<Callout>
  For detailed standards, see the modular pages: [TypeScript](/docs/contributing/coding-standards/typescript), [React](/docs/contributing/coding-standards/react), [Extension](/docs/contributing/coding-standards/extension), and [Reliability](/docs/contributing/coding-standards/reliability).
</Callout>

## Core Principles

- Use TypeScript with **strict type checking** enabled
- Prefer `const` over `let`; avoid `var`
- Keep modules small and single-responsibility
- Co-locate related hooks and components
- **Never log secrets**, API keys, or PII

## TypeScript

### Strict Typing

Use explicit types. Avoid `any`:

```typescript title="Good"
function processMessage(message: ChatMessage): ProcessedMessage {
  return { ...message, processed: true };
}
```

```typescript title="Bad"
function processMessage(message: any): any {
  return { ...message, processed: true };
}
```

### Type Imports

Use `import type` for type-only imports:

```typescript title="Good"
import type { WriteTone, RewritePreset } from '@cognito/shared';
import { TONE_INSTRUCTIONS } from '@cognito/shared';
```

### Path Aliases

**Always use path aliases** instead of relative paths:

| Alias | Maps To | Example |
|-------|---------|---------|
| `~*` | `./src/*` | `import { x } from '~/utils/helper'` |
| `@/*` | `./src/*` | `import { Button } from '@/components/ui/Button'` |
| `@assets/*` | `./assets/*` | `import icon from '@assets/icon.png'` |
| `~logger` | `./src/logger` | `import { createLogger } from '~logger'` |

<Callout type="warn">
  Never use `../../` or `../../../` patterns. Use path aliases configured in `tsconfig.json`.
</Callout>

## React 19

Cognito uses **React 19** with updated patterns.

### Ref as Prop

React 19 passes `ref` as a regular prop:

```typescript title="React 19 Pattern"
interface Props {
  ref?: React.RefObject<HTMLDivElement | null>;
  className?: string;
}

function MyComponent({ ref, className }: Props) {
  return <div ref={ref} className={className} />;
}
```

### useRef Null Handling

Always include `null` in the type:

```typescript title="Correct"
const inputRef = useRef<HTMLInputElement | null>(null);
```

```typescript title="Incorrect - won't compile"
const inputRef = useRef<HTMLInputElement>(null);
```

## State Management

Cognito uses **Zustand** for state management.

### Selective Subscriptions

<Callout type="warn">
  **Always use selectors** to avoid infinite re-render loops. Never subscribe to the entire store.
</Callout>

```typescript title="Good - selective subscription"
const messages = useChatStore((state) => state.messages);
const addMessage = useChatStore((state) => state.addMessage);
```

```typescript title="Bad - causes infinite re-renders"
const store = useChatStore();
```

### Available Stores

| Store | Purpose |
|-------|---------|
| `useSettingsStore` | User preferences |
| `useModelStore` | AI model config |
| `useChatStore` | Messages, threads |
| `useToolsStore` | Tool state |
| `useUINavigationStore` | UI navigation |
| `useMcpStore` | MCP servers |
| `useVoiceModeStore` | Voice settings |
| `useApprovalStore` | Tool approvals |

## CSS Guidelines

### CSS Scoping

<Callout type="warn">
  **Never write broad CSS selectors** that affect unrelated components. Always use unique, specific class names.
</Callout>

```css title="Bad - affects all spans"
.group:hover span { max-width: 50px; }
```

```css title="Good - scoped to component"
.my-feature-btn:hover span { max-width: 50px; }
```

### Tailwind CSS

Use Tailwind utilities. Avoid custom CSS when possible:

```tsx title="Good"
<button className="px-4 py-2 bg-blue-500 text-white rounded cursor-pointer">
  Click
</button>
```

**Required patterns:**

| Pattern | Use Case |
|---------|----------|
| `cursor-pointer` | All clickable elements |
| `mcp-scrollable` | Scrollable containers |
| `type="button"` | Buttons that shouldn't submit forms |

## Environment Variables

### Centralized ENV Module

<Callout type="warn">
  **Always use the `ENV` module** from `@/utils/env`. Never access `import.meta.env` or `process.env` directly.
</Callout>

```typescript title="Correct"
import { ENV } from '@/utils/env';
const backendUrl = ENV.BACKEND_API_URL;
```

```typescript title="Wrong"
const backendUrl = import.meta.env.WXT_BACKEND_API_URL;
```

## Logging

Initialize a module-scoped logger with a category:

```typescript title="Logger Usage"
import { createLogger } from '~logger';
const log = createLogger('FeatureName', 'CATEGORY');
```

| Category Group | Examples |
|----------------|----------|
| **MCP** | `MCP_CLIENT`, `MCP_TOOLS`, `MCP_AUTH` |
| **Tools** | `TOOLS_REGISTRY`, `TOOLS_EXECUTION` |
| **AI** | `AI_CHAT`, `AI_PROMPTS`, `AI_VOICE` |
| **UI** | `UI_CHAT`, `UI_SETTINGS`, `UI_SIDEPANEL` |
| **System** | `BACKGROUND`, `STORAGE`, `NOTIFICATIONS` |

## Security

### Sensitive Data Handling

**Never capture sensitive input values** when extracting DOM data:

```typescript title="Sensitive Input Detection"
function isSensitiveInput(input: HTMLInputElement): boolean {
  // Type-based
  if (input.type === 'password') return true;
  
  // Autocomplete-based
  const sensitiveAutocomplete = ['cc-number', 'cc-csc', 'current-password'];
  if (sensitiveAutocomplete.includes(input.autocomplete)) return true;
  
  // Pattern-based
  const pattern = /password|card|cvv|ssn|secret|pin/i;
  if (pattern.test(input.name + input.id)) return true;
  
  return false;
}
```

**Security requirements:**

- Add `// SECURITY:` comments when stripping sensitive data
- Check at **multiple layers**: extraction, formatting, transport
- Never pass API keys in URL query parameters; use headers

## AI SDK v6

Cognito uses **Vercel AI SDK v6** for AI interactions.

### Human-in-the-Loop Approval

For sensitive browser actions, implement tool approval:

| Component | Purpose |
|-----------|---------|
| `TOOLS_REQUIRING_APPROVAL` | List of tools needing approval |
| `TOOL_APPROVAL_CONFIG` | Per-tool domain extraction |
| `approvalStore` | Approval preferences (Zustand) |
| `CompactToolRenderer` | Approval UI rendering |

```typescript title="Tool UI Registration"
registerToolUI('toolName', (state: ToolUIState, options) => {
  return <CompactToolRenderer state={state} addToolOutput={options?.addToolOutput} />;
});
```

### Data Stream Protocol

Text content must use the complete message lifecycle:

```typescript title="Correct - Complete lifecycle"
writer.write({ type: 'text-start' });
writer.write({ type: 'text-delta', textDelta: 'Response...' });
writer.write({ type: 'text-end' });
```

<Callout type="warn">
  Missing `text-start` or `text-end` causes stream parsing errors.
</Callout>
