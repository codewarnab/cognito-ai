Thank you for your interest in contributing to **Cognito AI**! This guide covers everything you need to get started.

## Ways to Contribute

| Contribution | Description |
|--------------|-------------|
| **Bug Reports** | Report issues on GitHub |
| **Feature Requests** | Suggest new features |
| **Documentation** | Improve or add docs |
| **Code** | Fix bugs, add features |
| **Testing** | Test and report findings |

## Quick Start

### Fork and Clone

```bash title="Terminal"
git clone https://github.com/YOUR_USERNAME/cognito-ai
cd cognito-ai
```

### Install Dependencies

```bash title="Terminal"
corepack enable
pnpm install
```

### Create a Branch

```bash title="Terminal"
git checkout -b feat/my-feature
```

### Start Development

```bash title="Terminal"
pnpm dev
```

### Build and Commit

```bash title="Terminal"
pnpm build
git commit -m "feat(extension): add my feature"
```

### Push and Open PR

```bash title="Terminal"
git push origin feat/my-feature
```

## Development Workflow

### Find an Issue

- Check [GitHub Issues](https://github.com/codewarnab/cognito-ai/issues)
- Look for `good first issue` or `help wanted` labels
- Comment on the issue to claim it

### Setup Environment

See [Dev Setup](/docs/contributing/dev-setup) for complete instructions.

### Make Changes

Follow the [Coding Standards](/docs/contributing/coding-standards):
- TypeScript with strict types
- React 19 patterns
- Zustand selective subscriptions
- CSS scoping

### Test Your Changes

```bash title="Terminal"
pnpm build
pnpm build:extension
pnpm type:check
```

### Submit Pull Request

See Pull Request Process below.

## Pull Request Process

### Branch Naming

```text
feat/feature-name     # New feature
fix/bug-description   # Bug fix
docs/topic            # Documentation
refactor/area         # Code refactoring
```

### PR Checklist

- [ ] Branch is up-to-date with `main`
- [ ] Code follows coding standards
- [ ] Types pass (`pnpm type:check`)
- [ ] Build succeeds (`pnpm build`)
- [ ] Commit messages follow conventions
- [ ] PR description explains changes

### Review Process

Submit your PR against the `main` branch. Automated checks run immediately. A maintainer reviews the code and provides feedback. Address any requested changes. The PR is merged once approved.

## Commit Conventions

Use [Conventional Commits](https://www.conventionalcommits.org/):

| Type | Description |
|------|-------------|
| `feat` | New feature |
| `fix` | Bug fix |
| `docs` | Documentation |
| `style` | Formatting (no code change) |
| `refactor` | Code restructuring |
| `test` | Adding tests |
| `chore` | Maintenance tasks |

### Scope (Package)

```text
feat(extension): add new feature
fix(webapp): resolve settings page issue
docs: update architecture guide
chore: update dependencies
```

### Examples

```bash
# Feature
git commit -m "feat(extension): add voice mode settings"

# Bug fix
git commit -m "fix(mcp): handle OAuth token refresh failure"

# Documentation
git commit -m "docs: add MCP setup guide"

# Breaking change
git commit -m "feat(backend)!: change API response format"
```

## Issue Reports

### Bug Reports

Include:
- Chrome version
- Extension version
- Steps to reproduce
- Expected vs actual behavior
- Console errors (if any)
- Screenshots (if applicable)

### Feature Requests

Include:
- Clear description of the feature
- Use case / motivation
- Proposed implementation (optional)

## Code of Conduct

- Be respectful and inclusive
- Focus on constructive feedback
- Help newcomers get started

## Getting Help

- Check existing documentation
- Search GitHub Issues
- Ask in PR comments
- Contact maintainers
